# レセプトチェック用ビューア（Chrome拡張機能）仕様書

## 1. 目的

M3デジカルでレセプトを作成すると「要確認レセプト一覧」（CSV / PDF）が出力される。
この一覧の各行について、対象のカルテを1件ずつ開いて修正する作業を楽にしたい。

**作業の流れ（繰り返し）**

1. デジカルでレセプト作成 → 「要確認レセプト一覧」が出る
2. 一覧の各行について、該当カルテを開いて修正
3. もう一度レセプト作成 → 新しい一覧が出る（修正済みの行は消えている）
4. 一覧が空になるまで 2〜3 を繰り返す

**この拡張機能でやること**

- 一覧ファイルを拡張機能に渡すと、専用ウインドウが開く
- 2ペイン構成：**左に一覧**（フィルタ・ソート可）、**右に該当カルテ**
- 左ペインは折りたためる。折りたたみ中はマウスを乗せると一時的に出てくる
- 行ごとに「済」チェック → 行が暗くなる
- 患者ごとに簡単なメモを書ける
- 新しい一覧を読み込み直すと、前回の作業状態（済・メモ）を引き継いだうえで差分がわかる

## 2. 入力ファイルの形式

実ファイル（CSV・PDF 各1件、1か月分）を解析した結果。
**実データはリポジトリに入れない**。テスト用データは `samples/` にある（すべて架空。詳しくは `samples/README.md`）。

### 2.1 CSV（メインの入力。v1 はこれだけ対応すればよい）

| 項目 | 内容 |
|---|---|
| ファイル名 | `要確認レセプト一覧_YYYYMMDD_HHMM.csv`（出力日時） |
| 文字コード | **Shift_JIS（CP932）**。BOMなし |
| 改行 | CRLF |
| クォート | なし（実ファイルでは値にカンマを含む行はなかった。念のため RFC4180 のクォートにも対応しておく） |
| 1行目 | ヘッダー。**11列**（データ列9個 ＋ `診療年月`, `2025年 12月` というメタ情報2個） |
| 2行目以降 | データ。**9列** |
| 並び順 | 患者番号の**文字列順**（`16033` が `158980` より後ろに来る）→ 診察日 |

**ヘッダー行（そのまま）**

```
患者番号,患者氏名,診察日,診療科,医師,保険,チェック区分,チェック内容,該当カルテ,診療年月,2025年 12月
```

→ 10・11列目は「診療年月 = 2025年 12月」というキーと値。データ行にはこの2列はない。

**データ列**

| # | 列名 | 例 | 備考 |
|---|---|---|---|
| 1 | 患者番号 | `123456` | 医院の患者番号。桁数は不定（5〜6桁を確認）。**数値としてソートする** |
| 2 | 患者氏名 | `山田　太郎` | 姓と名の間は全角スペース。全角英字の外国人名もある（`ＳＡＭＰＬＥ　ＪＯＨＮ　ＤＯＥ`）。**フリガナはない** |
| 3 | 診察日 | `10/7` | `M/D`。ゼロ埋めなし。年は診療年月かURLから取る |
| 4 | 診療科 | `01:精神科・心療内科` | `コード:名前` |
| 5 | 医師 | `00001:山田　一郎` | `コード:名前` |
| 6 | 保険 | `国保 精神通院（21） 自立支援補助（21）` | 半角スペース区切りで複数。重複することもある（`精神通院（21） 精神通院（21）`） |
| 7 | チェック区分 | `公費` / `適応症` | 実ファイルではこの2種類のみ。**他の値も来る前提で、固定リストにしない** |
| 8 | チェック内容 | 下記参照 | 1行＝1つの指摘 |
| 9 | 該当カルテ | `https://digikar.jp/#/karte/patients/9000123/20251207` | 後述 |

**チェック内容のパターン（実ファイルで確認したもの）**

- `公費(負担者番号なし) 受給者番号が登録されていません。`
- `公費21XXXXXX 受給者番号が登録されていません。`（8桁の負担者番号入り）
- `<薬剤名>：適応症がついていません。`（全角コロン。薬剤名は全角英数）

**該当カルテURL**

```
https://digikar.jp/#/karte/patients/{カルテ内部ID}/{YYYYMMDD}
```

- `カルテ内部ID` はデジカル内部のIDで、**患者番号とは別物**（例：患者番号 123456 → 内部ID 9000123）
- 日付部分は診察日。同じ患者でも日付が違えばURLも違う
- ハッシュルーティング（`#/...`）の SPA。同じタブで `#` 以降だけ変えれば画面全体の再読み込みなしで切り替わる可能性が高い（要検証）

**1患者・1日で複数行になることがある**

- 同じ患者・同じ日に「公費」と「適応症」が両方出る
- 同じ患者・同じ日に適応症が薬ごとに複数出る
- 同じ患者が複数の日に出る（毎週通院なら4行など）

→ 左ペインは「患者ごとにまとめる表示」と「1行ずつのフラット表示」を切り替えられるとよい。

**実ファイルの規模**：データ55行 / 患者約40人（35行が公費、20行が適応症）。数百行程度まで想定すれば十分。

### 2.1.1 パスワード付き ZIP（0.3.0〜）

実際の一覧は、パスワード付き ZIP（中に CSV が1つ）で届く。パスワードは毎回同じ。

- ZIP のままドロップできる。ZipCrypto と AES（128/192/256）の両方に対応（外部ライブラリなし。AES は WebCrypto）
- パスワードは `chrome.storage.local` に記憶できる（初回にダイアログで入力。⚙ で変更・消去）。記憶したパスワードで開けなければもう一度聞く
- 中のファイル名は Shift_JIS／UTF-8 のどちらでもよい。CSV が複数あればすべて読み込む
- 出力日時は中の CSV の名前から取る。取れなければ ZIP の名前から取る

### 2.2 PDF（v2 以降。対応しなくてもよい）

- ファイル名：`要確認レセプト一覧_YYYYMMDD.pdf`。A4縦、今回は2ページ
- 列：`NO` / `患者番号` / `カルテ日付` / `保険` / `保険・公費・未会計`（○印） / `チェック内容`
- **CSV と比べて情報が少ない**：患者氏名・医師・診療科がない。保険欄は途中で切れている
- 患者番号とカルテ日付には**リンク注釈**が付いている
  - 患者番号のリンク：`.../patients/{内部ID}/{出力日}`（※診察日ではなく出力日）
  - カルテ日付のリンク：`.../patients/{内部ID}/{診察日}`
  - **カルテ日付のリンクの集合と、CSVの「該当カルテ」URLの集合は完全に一致する**（実ファイル同士で確認済み：どちらも重複を除いて49件）。これまで手作業ではPDFの日付リンクからカルテを開いていたので、CSVのURLで開けば同じ動きになる
- ○印は チェック区分 が「公費」の行に付く
- テキストは抽出できるが癖がある
  - 見出しは太字を「2回重ねて描画」しているため、文字が重複して出てくる（`患患者者番番号号`）
  - 保険欄は全文が書かれていて、セルからはみ出た部分を切り取って隠しているだけ。そのため、隠れている続きの文字も抽出される
  - 英数字（DejaVuSans）と日本語（IPAGothic）でフォントが分かれている
- 対応するなら pdf.js でリンク注釈（URL）と同じ高さのテキストを拾う方式になる。**CSV でやれることが全部できるので、優先度は低い**

### 2.3 一覧が空の場合

**未確認**。おそらくヘッダー行のみのCSVになる（`samples/round3_*.csv` はその想定で作ってある）。
0行のファイルや、ファイル自体が出ない可能性もあるので、どれでも落ちないようにする。

## 3. 画面

### 3.1 起動とファイルの読み込み

- 拡張機能アイコンをクリック → ビューアウインドウを開く（すでに開いていれば前面に出す）
- ビューアの画面にファイルをドラッグ＆ドロップ、または「ファイルを選択」ボタン
- ※ Chrome の仕様上、ツールバーのアイコン自体にファイルをドロップすることはできない
- 読み込み済みのデータがあれば、ウインドウを開いた時点で前回の状態を表示する

### 3.2 レイアウト

```
┌──────────────┬───────────────────────────────────────┐
│ [≡] 2025年12月分  │                                               │
│ 前回108→今回23件 │                                               │
│ [検索______]      │                                               │
│ 区分[全▼] 医師[全▼]│         該当カルテ（デジカル）                │
│ 状態[未▼] 並び[▼] │                                               │
│──────────────│                                               │
│▼ 123456 山田 太郎 │                                               │
│  □ 10/7  公費 …   │                                               │
│  ■ 10/14 公費 …   │ ← 済は暗転                                   │
│  📝 メモ…          │                                               │
│▶ 234567 佐藤 花子 │                                               │
└──────────────┴───────────────────────────────────────┘
```

- **左ペイン**：一覧。幅はドラッグで変更でき、幅は保存する
- **折りたたみ**：[≡] ボタンまたはショートカットで折りたたむ。折りたたみ中は左端に細い帯だけ残り、マウスを乗せると一覧が右ペインの上に重なって出てくる（離れたら引っ込む）。ピン留めで固定表示に戻す
- **右ペイン**：一覧で選んだ行のカルテ（3.5 参照）

### 3.3 一覧の項目と操作

- 表示：患者番号、氏名、診察日、チェック区分（色分けバッジ）、チェック内容、保険（短縮表示＋ツールチップ）
- **行をクリック** → 右ペインにその行のカルテ（その診察日）を表示。選択中の行をハイライト
- **済チェック**：行ごと。チェックすると行を暗く（グレーアウト）する。患者単位で「この患者の全行を済」もできる
- **メモ**：患者ごとに1つ（カルテ内部IDで紐付け）。短いテキスト。メモがある患者はアイコン表示
- **キーボード操作**（あると便利）：↑↓で行移動（移動と同時にカルテ切替）、Space で済の切り替え、M でメモ、[ で左ペイン折りたたみ

### 3.4 フィルタとソート

- フィルタ
  - 状態：未のみ / 済のみ / すべて（初期値：未のみ…は好みが分かれるので「すべて＋済は暗転」でもよい）
  - チェック区分（CSVに出てきた値から自動で選択肢を作る）
  - 医師、保険（「精神通院」「生活保護」などを含むかどうか）
  - 差分ステータス（新規 / 継続 / 要再確認、4章参照）
  - テキスト検索（患者番号・氏名・チェック内容を対象）
  - 「負担者番号なしを隠す」（0.4.0〜、既定でオン）：チェック内容が `公費(負担者番号なし)` で始まる行を隠す。`公費21XXXXXX …` のように負担者番号がある行は隠さない。隠した行は件数・「全て済」の対象外
- ソート：患者番号（**数値順**）、氏名、診察日、チェック区分、状態
- 表示切替：患者ごとにまとめる ／ 1行ずつ

### 3.5 右ペイン（カルテ表示）の実現方法 ★最初に検証が必要

デジカルのページを拡張機能のページ内に表示できるかどうかで実装方式が変わる。
外部から `digikar.jp` を確認しようとしたが、IP制限のようなものがかかっていてヘッダーを確認できなかった。**院内の端末で検証すること。**

| 方式 | 内容 | 長所 | 短所・リスク |
|---|---|---|---|
| **A. iframe 埋め込み** | 拡張機能のページ内に `<iframe src="https://digikar.jp/#/...">`。`X-Frame-Options` や CSP の `frame-ancestors` で拒否される場合は `declarativeNetRequest` でそのヘッダーを外す | 1ウインドウで完結し、理想に一番近い | ログインCookieがサードパーティ扱いでブロックされる可能性。デジカル側の仕様変更で壊れうる。ヘッダーを外すことの是非 |
| **B. 2ウインドウ連動** | 一覧ウインドウ（細め）とデジカルのウインドウを左右に並べて開く。行をクリックしたら `chrome.tabs.update` でデジカルのタブのURLを書き換える | 確実に動く。デジカルは普通のタブなのでログイン状態もそのまま | 2つのウインドウになる。位置合わせが必要（`chrome.windows.create` で左右に配置） |
| **C. サイドパネル** | Chrome のサイドパネル（`chrome.sidePanel`）に一覧を出し、メインのタブでカルテを開く | Chrome標準のUI。タブと自然に連動 | サイドパネルは右側が既定（Chromeの設定で左に変更可）。幅の制約あり |

**結果（2026/11）**：院内PCで方式Aを試したところ、デジカルが埋め込みを拒否した（「digikar.jp で接続が拒否されました」）。ヘッダーを外す方法は取らず、**方式Bに決定**。左右の折りたたみ（3.2）は方式Bでは不要なので実装しない。

**当初の進め方の提案**：最初に方式Aが院内の環境で動くか小さく試す（ログインが通るか、ページ遷移がちゃんと効くか）。ダメなら方式Bで実装する。
どの方式でも左ペイン側のコードは同じになるように、「カルテを表示する」部分は差し替え可能にしておく。

## 4. 再読み込み（2回目以降のリスト）

これがこの拡張機能のキモ。

### 4.1 行の同一性（キー）

```
key = カルテ内部ID + "|" + 診察日(YYYYMMDD) + "|" + チェック区分 + "|" + チェック内容
```

- 患者番号ではなくURLのカルテ内部IDを使う（URLに必ず入っていて、日付も取れる）
- 完全一致の行はないことを確認済み（実ファイルで重複行0件）。万一重複したら連番を付けて区別する

### 4.2 差分の判定

同じ診療年月の前回データがあるとき、新しいファイルの各行を次のように分類する。

| 分類 | 条件 | 表示 |
|---|---|---|
| **解消** | 前回あった行が今回ない | 一覧からは消す（「解消済み N件」として折りたたみ表示で見られる程度でよい） |
| **継続** | 前回も今回もある・前回「未」 | 普通に表示 |
| **新規** | 前回なかった行が今回ある | 「NEW」バッジ |
| **要再確認** | 前回「済」にしたのに今回もまだある | **警告色で目立たせる**。済は自動で外す（直したつもりで直っていない行） |

- 読み込み時に要約を出す：例「前回 108件 → 今回 23件（解消 86／継続 22／新規 1）。済にしたのに残っている行：3件」
- メモは患者単位なので、そのまま引き継ぐ
- 一覧が空になったら「すべて解消しました」と表示

### 4.3 診療年月が違うファイルを読み込んだとき

- 診療年月ごとに別のデータとして保存する（11月分を読み込んでも10月分の状態は消さない）
- ヘッダーから診療年月が取れない場合は、URLの日付から推定する

## 5. データの保存とプライバシー

**このデータは患者の個人情報（氏名・保険・薬剤）である。**

- 保存先は `chrome.storage.local` のみ（そのPCのそのChromeプロファイルの中だけ）
- **外部への送信は一切しない**。解析ツール・外部フォント・CDN も使わない（全部拡張機能に同梱）
- 保存するもの：診療年月ごとの「最新の一覧」「各行の済状態」「患者メモ」「読み込み履歴（日時・件数）」、UI設定（左ペイン幅など）
- 「この月のデータを削除」「すべて削除」ボタンを用意する
- 古い月のデータは一定期間（例：3か月）で自動削除するオプション
- リポジトリには実データを絶対に入れない（`.gitignore` 参照）。テストは `samples/` のダミーデータで行う

## 6. 技術メモ

- **Manifest V3**
- 権限は最小限：`storage`、方式によって `declarativeNetRequest` / `sidePanel` / `tabs` / `windows`、host permission は `https://digikar.jp/*` のみ
- ビルドなし（素の HTML / CSS / JavaScript、ES Modules）を推奨。院内PCで「パッケージ化されていない拡張機能を読み込む」だけで使えるようにする
- Shift_JIS の読み込みは `new TextDecoder('shift_jis')` で可能（外部ライブラリ不要）
- CSV のパースは自前の小さな関数で十分だが、クォート・末尾の空行・列数違いに耐えるようにする

## 7. 受け入れ条件（サンプルで確認できること）

`samples/` のダミーデータを使う。

1. `round1_*.csv` を読み込むと 108行が表示され、診療年月「2025年11月」が表示される
2. 患者番号ソートが数値順になる（`16033` が `121146` より前）
3. 全角英字の氏名（`ＳＡＭＰＬＥ　ＪＯＨＮ　ＤＯＥ`）が文字化けせずに出る
4. 行クリックでその行のURL（`.../patients/{内部ID}/{日付}`）のカルテが右ペインに出る（※ダミーIDなので実際のカルテは出ない。URLが正しいことを確認）
5. 何行か「済」にしてメモを書く → ウインドウを閉じて開き直しても残っている
6. `round2_*.csv` を読み込むと 23行になり、要約に「解消 86／継続 22／新規 1」と出る（新規は患者番号 `400001`）
7. 手順5で「済」にした行のうち round2 にも残っている行は「要再確認」になる
8. `round3_*.csv`（ヘッダーのみ）を読み込むと「すべて解消」と出る
9. 左ペインの折りたたみ・マウスを乗せると表示・ピン留めが動く
10. `original_anon/` の CSV（実ファイルを匿名化したもの。55行・40人・診療年月 2025年12月）が読み込める
11. （PDF対応する場合）`original_anon/` の PDF を読み込むと、CSV と同じ49件のカルテURLが得られる

## 8. 決めていないこと（実装しながら相談）

- 右ペインの方式（3.5 の検証結果しだい）
- 状態フィルタの初期値（未のみ／すべて）
- メモを患者単位にするか、行単位にもするか（とりあえず患者単位）
- ダウンロードフォルダを監視して、新しい一覧CSVが落ちてきたら自動で読み込む機能（`chrome.downloads` で検知はできるが、ファイルの中身を読むには「ファイルのURLへのアクセスを許可する」設定が必要。v2 以降の候補）
